# 民法典适用（civil-code-advisor）

底座：《中华人民共和国民法典》1260 条全文（国家法律法规数据库版，逐条校验无缺号）+ 271 件现行有效司法解释全文（其中 252 件取自 flk 镜像，19 件为 2026 年 6—9 月新发布/新修正件，另行补抓并双源核验）+ 4 份审判工作会议纪要参考层。

蒸馏深度：民法典 **每一条**都有要件卡片（1260/1260，缺号 0）；九件民法典冠名配套司法解释 **每一条**都有速查卡（434 条）；请求权基础与争点路由 220 个节点；衔接层 5 张表（时间效力决策树、新旧法对照与冲突表、期间时效 71 项、举证责任 44 项、案由映射 60 项）。

## 标准工作流

1. **定事实时点**：先问法律事实发生在 2021-01-01 前还是后，落在哪部旧法施行期内。这一步决定后续全部检索，跳过必错。
2. **定争点**：在 `distill/请求权基础/` 用 Grep 搜关键词（如「解除」「善意取得」「保证期间」「优先受偿」），拿到该争点的要件树与条文清单。
3. **逐条落到卡片**：按争点里的条号去 `distill/要件卡片/` 取该条的要件、效果、配套解释、易错点。
4. **回原文校验**：写进任何对外文书前，必须 Grep 原语料确认（见下）。
5. **查冲突**：同一事项若可能有多件解释覆盖，查 `衔接适用/02` 的冲突表与 `index/transition.tsv` 的施行衔接条款，确认采新版还是按受理时点分界。

## 引用前三查（硬要求）

- 查条号是否存在且内容相符：`grep -n "第六百八十六条" corpus/mfd/民法典_全文.md`
- 查解释条是否真的对应：`grep -n "六百八十六" corpus/ssjf/T1_008_*.md`；无命中说明该解释未明示援引，属**功能对应**，引用时只引解释本身的规则文字，不要写成"某解释第X条规定民法典第Y条应当如何"。
- 查效力：`index/corpus_files.tsv` 的 `eff_date` 与 `tier`；文件名带 `T?_9xx_` 的是 2026 补抓件，标注了抓取来源与核验状态，对外使用前必须回查该条来源链接。

卡片与速查表里的「配套解释」列有两类：原文明示援引、以及蒸馏时判定的功能对应（`解释速查` 里以 `(推定)` 标记）。要件卡片未带标记，一律按功能对应对待，须回查原文。

## 边界与已知缺口

- 只覆盖民事/商事/民事诉讼与执行衔接类司法解释。刑事、行政、国家赔偿、区际司法协助（内地与港澳、涉台）已排除，排除清单见 `index/excluded_manifest.md`，需要时可重新纳入重建。
- T4 扩展层（知产、环境资源、海事海商、国家赔偿等 87 件）只入全文与索引，未做逐条蒸馏；这些领域要深度分析需另行蒸馏。
- 会议纪要属审判指导文件，与司法解释效力不同，卡片中若出现"纪要"字样均为参考意见。
- 2026 年补抓件（`T?_9xx_`）以最高法官网正文页为准并做过双源比对，其中法释〔2026〕15号在官网无逐条正文页，采用两个镜像互证，对外引用前回查。
- 法律会变动。凡涉及施行日期在近期、或可能被新解释修改的条文，用 `pkulaw`/`flk` 复核效力后再落纸（技能内置 `tools/refresh_laws.sh` 拉取镜像更新）。

## 输出纪律

- 援引一律写"《民法典》第X条第X款第X项"，司法解释写"《名称》（法释〔YYYY〕N号）第X条"。
- 不给结论不给依据的句子；不给没有条号的"根据相关规定"。
- 区分规范功能：原则宣示条款、定义条款、准用条款不能作为独立请求权基础。
- 卡片是蒸馏物，不是原文。对外文书引原文，原文只从 `corpus/` 取。
